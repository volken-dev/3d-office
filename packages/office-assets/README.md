# office-assets

The office and robot models, generated entirely from code as glTF: Isaac's blocky robot (built on the skeleton and 12 base clips of a source rig, everything else his own) and the agent office it works in. Robots stand for AI agents; where a robot is and what it's doing shows that agent's state, and **colour means status**: green (working, deploying, done), yellow (idle, charging, arriving), orange (waiting for the user), red (error).

Nothing is hand-modelled and the shipped files are never hand-edited: change a generator or the layout, rebuild. This package is build-time only; the browser loads the compressed output from `packages/scene/assets/models`. It was `~/Projects/agent-office` until 2026-10-25 (#97), moved here unchanged byte for byte.

## Commands

```bash
bun run models            # everything below, in order
bun run models:textures   # procedural textures -> out/textures/*.png
bun run models:robot      # out/raw/robot.glb (needs the source rig)
bun run models:robot-lite # out/raw/robot-lite.glb (LITE=1, needs the source rig)
bun run models:minibot    # out/raw/minibot.glb
bun run models:office     # out/raw/office.glb (reads the textures)
bun run models:compress   # meshopt + WebP -> packages/scene/assets/models/{office,robot}.glb, out/{robot-lite,minibot}.glb
bun run models:check      # every shipped file against packages/scene/assets/asset-contract.json
bun run models:movement   # office-sim's movement test on the shipped office
bun run models:validate   # Khronos glTF validator (0 errors; the robots carry 2 harmless NODE_SKINNED_MESH_NON_ROOT warnings)
```

- **Generators run under node 22 with type stripping, not bun**: bun's maths differs from V8's in the last bit, and a rebuild should reproduce the committed files byte for byte, which is how a refactor proves it changed nothing. So `src/robot`, `src/office`, `src/compress` and their scripts use erasable TypeScript only, import relative files with `.ts`, and never import a workspace package. The contract check and the tests run under bun and may use `@the-delegation/office-sim`.
- **The source rig** `rig/character-rig.glb` is a personal-use asset: it stays on this machine and is gitignored (`OFFICE_RIG` overrides the path). Only the robot builds need it; the committed GLBs mean dev, CI and the web build never do.
- **robot-lite and minibot** are built and checked but not loaded by the scene yet, so they live in the gitignored `out/`.
- The office build's switches: `LOD=0` keeps authored tessellation, `TRIS=1` prints triangles per item type, `ZFIGHT=warn` downgrades the z-fighting check, `NAV_PNG=out/nav.png` dumps the walk grid (white reachable, grey cut off, red POIs) when a layout change breaks reachability, `LAYOUT` points at another layout. The robot build's: `Q` mesh density, `PAL_JSON='{"primary":"#46c27a"}'` a palette override.
- After a visual change, look at it in the app (`bun run dev`) before calling it done.

## Layout

| Path | What |
|---|---|
| `src/office/office-layout.json` | **The office, as data** (validated by `office-layout-schema.ts`): `agents.max`, `statusColors`, room and base floor, walls, windows, door, zones, glass, items (incl. `desk_grid` work pods and `charge_row` docking bays, one each per agent), spawns, areas, night lights, and the agent-state mapping with each state's `color`. Most office changes are edits here. |
| `src/office/` | The office generator: `build-office-document.ts` runs it in order. `items/build-item.ts` picks a builder per item `type` (grouped by area in `items/`); `frame-builder.ts` is the drawing kit (`box`, `superEllipsoid`, `tube`, `curved`, `outline`, `rectangle`, `polygon`, `block` for walk-grid obstacles, `pointOfInterest`); `stencil-text.ts`, `seats.ts` (`officeChair`, `cockpitSeat`), `plants.ts` (`PLANT_GROWERS`: leafy, snake, grass, fiddle, olive), `tessellation-level.ts` (small round parts tessellated by size). Then the walk grid, approach points, overflow stand spots, agent-state capacity, the z-fighting check, palette and screen-atlas merging, baked AO and the `Ambient` clip. |
| `src/office/textures/` | Procedural textures (code screens, dashboards, CI pipeline, skylines, the agent board sample, the lab floors). Seeded and deterministic. |
| `src/robot/` | The robot generator: reads the rig's skeleton and 12 base clips, builds new geometry (`parts/`, one file per part), adds joints, face morphs, extra clips and spring-simulated secondary motion (`animation/`). `LITE=1` builds robot-lite. `minibot/` builds the minibot. |
| `src/compress/` | The shipping step: meshopt + quantization, redundant animation keys dropped, WebP textures; robot-lite's clips compared with the robot's and stripped. |
| `src/contract/` | The asset contract checker (`check-contract.ts`), also run as `test/contract/check-contract.test.ts` in CI. |
| `packages/scene/assets/asset-contract.json` | **The asset contract**: everything the scene and office-sim may rely on (joints, morph targets, clips and poses, materials, node names and prefixes, POI kinds and ids, night lights, scene extras, agent states, extensions, per-file budgets). |

## World conventions (keep these stable: the scene and office-sim depend on them)
These are codified in `packages/scene/assets/asset-contract.json`. A change that breaks the contract fails `bun run models`: if the change is intended, update the contract in the same edit and bump `contractVersion` (major = rename/removal, minor = addition, patch = notes only), and update the scene and office-sim to follow.
- Units metres, +Y up. Characters face **+Z** at rest. Small scale: robot ≈1.25 m to head top (1.47 m with antenna); desk top 0.50 m; seat 0.30 m; counter 0.55 m.
- Overhead camera looks from **+X/+Z**, so north (z min) and west (x min) walls are full height (2.2 m); south/east walls are low cutaway walls.
- **Agents scale from `agents.max`** (10) in `office-layout.json`: slot N = work pod N + docking bay N + status texel N. `desk_grid` emits pods 1..max in rows of `cols` (the build throws if they don't fit the zone), and every agent state must hold max agents (overflow stand spots are generated; the contract check enforces capacity). **Sessions beyond max queue in the lobby** (state `queued`: queue position N waits on `poi-stand-entry-N`, 1 = nearest the door, `assign: "position"`; Isaac had dedicated queue spots and their paint removed as clutter; the `Roster` is the reference; Isaac chose this over hot-desking or a bigger office). To raise max: each 5 agents is another pod row (~2.6 m) and 5 more bays (beyond ~11 bays the dock wall is full: needs a second rack row); raise `agents.max` in layout + contract.
- **Office plan (contract 5.0, 21 × 14 m, x -11..10)**: **docking bay** behind glass on the west (4.5 m deep; zone `server_room`): one bay per agent = glass-door rack + bay plate 01–10 + docking cradle; cable tray with coolant pipes into the cooling unit and two rack-top shuttles; a DOCKING BAY floor stencil across the open middle (Isaac rejected a glowing core centrepiece and had the CHARGING DOCK portal removed so the stencil reads); a `flash_station` whose `data_link` glass tube carries capsules through the glass into the fabricator's roof | a glass **meeting room** north-west (`control_room`: video wall + curved console, seats = sit_idle 1, 2, 5, 6) | **work pods** in 2 rows of 5 facing **west** toward the dock (`desk_grid` → `console_station`: one continuous console per row, curved screen toward the camera, `cockpit` seat with a data umbilical so a seated robot reads as plugged in, frosted wings, plate 01–10, status strip + status ring on the floor; the wall behind them is bare apart from the steel planter troughs: Isaac had the framed print removed) | **training pods** (sit_idle 3–4) and a **maintenance bar** (coolant / oil dispensers = use_coffee, service counter = coffee_chat) north-east | the **lobby** by the **door (middle of the east wall)**: ARRIVALS scanner gate, hang-out `seat_row`s facing each other across a `low_table` (sit_idle 7–8; beam seating as a *style* for hanging out, not literal train-station seats), wayfinding totem, `showcase`, the live **agent board** on the north wall (node `agent-board`, material `agent_board`, scene extras `agentBoard`) | a painted **concourse** from the door to the dock; the launch pad on the open floor above the factory (walkways must stay logical and spacious: aisles ≥ ~1.2 m, the aisle between pod rows lines up with a gap in the factory rails) | steel guard rails, then the **agent factory** on the **south**: 8 steel workbenches where robots face the camera and hammer / tinker under a gantry with station plates 01–08, freshly built (unpainted) robots riding the belt from the fabricator (west) to dispatch (east), two swinging robot arms on hatched keep-out paint, aisle markings + an "AGENT FACTORY" stencil. One pale lab floor (raised-access panels, `floor_lab`) everywhere, perforated in the dock (`floor_lab_perf`). Isaac wants this functional layout with a futuristic-factory feel (no office furniture: they had the sofas, rugs, bookshelves and kitchenette replaced); they rejected a radical re-plan ("The Pass") and found mixed floor finishes made the sections look unrelated.
- **Colour means status.** The decor is muted on purpose (pale lab floor, oak furniture, steel, navy / teal / plum fabrics, deep greens, muted books and prints) so the only saturated colours are the robots and their desk / bay lights: statusColors green `#2fbf71`, yellow `#f2c230`, orange `#f2832e`, red `#e5484d` (contract `statusColors`). Don't add saturated green / yellow / orange / red decor.
- **POIs**: empty nodes `poi-<kind>-<n>`; rotation 0 faces +Z. Kinds: `sit_work` (pod N), `charge` (bay N), `ship` 1–8 (workbenches), `sit_idle` 1–8 (meeting-room console 1, 2, 5, 6; training pods 3–4; lobby hang-out 7–8), `use_coffee` (maintenance bar), `coffee_chat` 1–3 (service counter), `idle-spawn` 1–5, `idle-area-<zone>`, and generated overflow spots `stand-<zone>-<n>`. Any `sit_*` kind is a seat (gets an approach point and Sit/Stand). Every POI has an **approach point** (scene extras `approach`) on the **walk grid** (scene extras `nav`, bit-packed, seats and furniture are obstacles), reachable from spawn 1: the generator throws otherwise.
- **Agent states** live in `office-layout.json > agentStates` (state -> `{ note, slots: [{ pois, clip, assign? }] }`, `poi-x-*` wildcards, `assign: "own"` = `poi-<kind>-<slot id>` (its pod or its docking bay), `assign: "position"` = `poi-<kind>-<queue position>`, **slots fill in order**, overflow last). Each state has a `color` (a statusColors key). States: working (own pod, green), shipping (workbenches: Hammer then Tinker, green), waiting_for_input (own pod, "?", orange), idle (meeting room / training pods / lobby hang-out / maintenance bar, yellow), paused_or_rate_limited (own bay, yellow), error (own pod, "!", red), done (dances in place at a workbench, green), arrive (door, yellow), queued (lobby queue, yellow); copied to the office scene extras. Entering/leaving seats uses the contract's `transitions` (Sit/Stand, plus Plug_In/Plug_Out at chargers).
- Node prefixes: `static-*` merged geometry per zone (`static-glass` transparent: glass + `frosted` pod wings; `static-screens` emissive screen faces); `agent-board` (the live board); `day-only-*` / `night-only-*` toggled by time of day; `night-light-*` = KHR_lights_punctual point lights, on at night only; `anim-*` = animated by the office clip `Ambient` (coolant vapour `anim-steam-N`, conveyor robots `anim-conveyor`, factory arm turrets `anim-arm-N`, rack shuttles `anim-shuttle-N`, data capsules `anim-link`; loop it: every loop must be seamless, e.g. a row slides exactly one spacing with identical items; nothing blinks: Isaac asked for no flicker); material `lamp_glow` should have emissive ~off by day; `navMesh` = the walk grid as geometry (hide in game). Opaque static geometry has baked AO in `COLOR_0` (floors are subdivided for contact shadows).
- **Shipped files are meshopt-compressed** (`EXT_meshopt_compression`, `KHR_mesh_quantization`, `EXT_texture_webp`): loaders need a meshopt decoder (three.js: `loader.setMeshoptDecoder(MeshoptDecoder)` from `three/addons/libs/meshopt_decoder.module.js`). Uncompressed copies are in `out/raw/`. Compression must keep material names (no material dedup) and empty leaf nodes (POIs).
- Office draw calls are merged: flat-colour materials collapse into one `palette` material per node (nearest-filtered colour / metal-rough / emissive textures, one 4×4 cell per original material; map in scene extras `palette`), screen faces into one `screens` atlas (`screenAtlas` extras = [u0,v0,u1,v1] per original screen texture). Materials kept separate on purpose because they're addressed by name: `status_glow`, `lamp_glow`, `border_glow`, `agent_board`, glass, frosted, floors, skies, navmesh. ~29 draw calls.
- Status lights: material `status_glow` (pod N's front strip + floor ring, docking bay N's rack strip + header + floor ring) samples texture `status_colors` (W×1, slot N = texel N-1, scene extras `statusColors` with `colors` and `off`); the product writes agent N's status colour there and on its robot's `primary` (queued agents have no slot, so no light). The scene swaps in a DataTexture at runtime (`packages/scene/src/office/status-lights.ts`). Compression keeps the texture although it's uniform by default (`prune({ keepSolidTextures: true })`).

## Robot facts
- Skeleton: the source rig's 10 joints (`root, hips, leg.L/R, spine, head, arm.L/R, lower.arm.L/R`) plus added joints `antenna`, `antenna_tip`, `zzz`, `cable`, `bubble_q` ("?"), `bubble_alert` ("!"), `hammer` (child of `lower.arm.R`; its local rotation cancels the forearm's bind rotation so its bind frame is world-aligned at the grip). Inverse bind matrices are extended in the generator; vertices are authored in bind-pose world space.
- `zzz`, `cable`, `bubble_q`, `bubble_alert`, `hammer` rest at **scale 0** (hidden); only their clips scale them to 1 (Charge/Plug_*, Sit_Wait/Wait, Sit_Sad, Hammer). Same trick works for any clip-only prop. **Tool icons** `icon_terminal`, `icon_search`, `icon_edit`, `icon_web` (head joints, above-left; bubbles are above-right) also rest at scale 0 but are **product-driven**: no clip touches them, the product scales the current tool's joint to 1. A dark badge with the glyph tubes running through it (both faces); the terminal `>_` is drawn per face so it never reads mirrored. Bubble glyphs are fixed to the head (a back copy reads correctly from behind); the product can billboard the joint if wanted.
- 24 clips: the 12 originals (Happy, Idle, Listen, LookAround, Pick, Sad, Sit, Sit_Idle, Sit_Work, Talk, Walk, Wave): their body channels are never modified: plus Dance, Jump, Celebrate (keyed with `makeClip`, rotations in bind-world axes) Charge (`deriveClip` from Sit_Idle's first frame + deltas) Sit_Sad (`deriveClip` from Sit_Work: the seated `error` state, slumped with a sigh, head shake and "!"), Sit_Wait / Wait (waiting for Isaac, "?"), Hammer / Tinker (`deriveClip` from Idle: the deploy line; the Hammer strike is the `hammer` joint turning about the grip like a wrist, landing ~0.28 m up and 0.33 m in front, which is where the workbench anvil plate is), and transitions Stand (Sit reversed), Plug_In / Plug_Out (Sit_Idle <-> Charge's first frame, cable grows). **One-shots** (`ONE_SHOT`: Sit, Stand, Plug_In, Plug_Out) simulate their generated layers once from rest with no loop closing.
- Every clip gets generated layers: antenna rotation (2-joint spring sim driven by the head's real motion), head squash/stretch (head scale was never animated in the originals), and face morph weights (per-clip table `FACE`).
- Face = one morphing primitive on the `face` node, 13 targets: blink, happy, sad, angry, wide, look_left/right/up/down, mouth_smile/open/flat/frown. Base mouth is collapsed (invisible): robot has no mouth unless a mouth target is weighted.
- **Crowd LOD** robot-lite (`out/robot-lite.glb`, not loaded by the scene yet) (`LITE=1`): same skeleton, joints, face morph targets and material names, so it can swap in for the full robot at runtime. **It ships with no clips**: play `robot.glb`'s clips on it (three.js binds tracks by node name; scene extras `animationsFrom: "robot.glb"`). `compressModel`'s script checks the clips match key-for-key before stripping them, so a generator change that makes them diverge fails the build. ~3.8k tris vs ~14.6k, 5 draw calls vs 7: coarser tessellation (`Q=0.3`), greebles skipped via `if (!LITE)`, body `screen` parts use `secondary` and body `eye` parts (Zzz) use `accent` (`LITE_MAT`).
- Materials (recolourable by name): `primary, secondary, metal, accent (emissive), screen, eye (emissive)`. `primary` is neutral grey by default: the product colours it by status. Palette override at build: `PAL_JSON='{"primary":"#46c27a"}' bun run models:robot`.
- The **head is wider than arm reach**: arms raised above ~horizontal disappear into it. Celebrate/Jump/Dance use arms-out poses for that reason, and Hammer uses a short low swing. The idle arms angle outward, so a world-X rotation lifts them rather than bringing the hands forward: add a z rotation (+ for arm.R, - for arm.L) to bring hands in front of the body.
- Charge plug position: the generator prints `CHARGE_PLUG [x,y,z]` (relative to the robot origin in the Charge pose). `office-layout.json` charge_row `plug` must match it so the cable meets the rack socket.

## Gotchas
- `superEllipsoidPart` exponents: smaller = boxier. Emit order matters only for the face primitive (morph target arrays are aligned to vertex order).
- Transparent materials (glass, frosted) shouldn't cast shadows; the renderer must disable it.
- Coplanar faces z-fight at overview distance: keep stacked decals/panels ≥4 mm apart (rack fronts, floor decals), and stop walls where a window/door frame starts rather than overlapping into it. The build now enforces this (z-fighting check); fix the geometry rather than reaching for `ZFIGHT=warn`. Stencil text (`floorStencil` / `wallStencil`) uses the 5×7 pixel font (`pixel-font.ts`); a missing glyph throws. Floor decals go at y ≥ 0.008 (floors are at 0.0015 / 0.003, plinth top at -0.006).
- `pottedPlant()` puts its pot on the floor (y 0); for something on a desk or shelf use a pot `superEllipsoid` plus `PLANT_GROWERS.<kind>` at that height.
- A stale contract once made new seat kinds play their seated clip at the approach point (a robot "straddling" the chair back): office-sim treats any unknown `sit_*` kind as a seat.
